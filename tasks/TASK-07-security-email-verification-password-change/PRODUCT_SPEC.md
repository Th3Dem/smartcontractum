# PRODUCT_SPEC.md — Продуктовая спецификация: Смена пароля через E-mail в «Безопасности» (TASK-07)

## 1. Цели и пользовательский опыт
Пользователь не должен видеть форму прямого ввода текущего пароля. Вместо этого предоставляется защищенный двухфакторный процесс смены пароля:
1. Кнопка «Сменить пароль».
2. Отправка 6-значного кода на подтвержденный E-mail пользователя.
3. Ввод кода с таймером повторной отправки.
4. Открытие формы ввода нового пароля с индикатором сложности.

---

## 2. Пользовательские сценарии (User Stories)
- **US-01 (Запрос смены пароля)**: Как пользователь, находясь на вкладке «Безопасность», я нажимаю кнопку «Сменить пароль» и система автоматически отправляет 6-значный код на мой E-mail.
- **US-02 (Ввод проверочного кода)**: Как пользователь, я ввожу код из почты в удобное поле. Если код верный, мне открывается экран задания нового пароля.
- **US-03 (Установка нового пароля)**: Как пользователь, я ввожу новый пароль (видя его сложность) и подтверждение, после чего пароль обновляется и выводится сообщение об успехе.

---

## 3. Критерии приемки (Acceptance Criteria)
1. **AC-01**: Текущий пароль не запрашивается и не отображается в открытом виде.
2. **AC-02**: На вкладке «Безопасность» отображается кнопка «Сменить пароль» с информационным блоком о привязанной почте.
3. **AC-03**: Реализован 3-шаговый мастер: 1) Запрос $\rightarrow$ 2) Ввод кода $\rightarrow$ 3) Новый пароль.
4. **AC-04**: Проверочный код высылается через реальный SMTP (Яндекс SSL 465) с временем жизни 10 минут.
5. **AC-05**: На этапе ввода кода действует таймер обратного отсчета 60 сек для повторной отправки.
6. **AC-06**: Поддерживается отмена на любом шаге с возвратом к исходному экрану.
