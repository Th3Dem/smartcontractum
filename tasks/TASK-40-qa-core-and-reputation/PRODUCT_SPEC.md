# PRODUCT_SPEC.md — Продуктовая спецификация Q&A ядра и репутации (TASK-40)

## 1. Бизнес-цель
Обеспечить персистентность базы знаний, позволив специалистам задавать вопросы, публиковать экспертные ответы, оценивать полезность и накапливать подтвержденную репутацию в SQLite.

## 2. Пользовательские сценарии (User Stories)
- **US-01 (Задать вопрос)**: Пользователь через кнопку `+ Создать` задает профессиональный вопрос с категорией, тегами и текстом. Вопрос сохраняется в БД и доступен всем участникам.
- **US-02 (Дать ответ)**: Профильный эксперт открывает вопрос и оставляет ответ. Ответ сохраняется и отображается в ветке решения.
- **US-03 (Принять лучшее решение)**: Автор вопроса может нажать «Принять ответ». Вопрос получает статус «Решено» (`is_solved = 1`), блок ответа подсвечивается зеленым, а автор ответа получает `+50` очков профессиональной репутации.
- **US-04 (Оценка полезности)**: Любой авторизованный специалист может нажать «Полезно ▲ / ▼», начисляя `+10` / `-5` очков репутации автору материала.

## 3. Критерии приемки (Acceptance Criteria)
- **AC-01**: Таблицы `feed_posts`, `feed_comments`, `user_reputation`, `feed_votes` создаются в `data/smartcontractum.db`.
- **AC-02**: Все созданные посты и вопросы персистентно сохраняются в SQLite и возвращаются через REST API `/api/feed/posts`.
- **AC-03**: Эндпоинт `POST /api/feed/posts/<id>/accept-answer` атомарно обновляет статус вопроса и начисляет +50 очков репутации автору ответа.
- **AC-04**: Эндпоинт `POST /api/feed/posts/<id>/vote` обновляет количество полезных отметок.
- **AC-05**: Все автоматические тесты проходят со 100% успехом.
