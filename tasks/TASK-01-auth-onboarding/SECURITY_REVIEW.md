## 2. Ключевые механизмы защиты

### 2.1. Криптостойкое хеширование паролей
- **Алгоритм**: `PBKDF2-HMAC-SHA256`
- **Количество раундов**: `100 000 итераций`
- **Соль (Salt)**: 16 байт (`secrets.token_hex(16)` = 32 hex-символа), генерируется криптографически случайно для каждой учетной записи.
- **Защита от открытого хранения**: Пароли пользователей никогда не сохраняются в открытом виде или в виде обратимого шифрования.

### 2.2. Защита от тайминг-атак (Timing Attacks)
- Сравнение вычисленного хэша и сохраненного хэша выполняется через `hmac.compare_digest`, исключающее определение длины и префикса совпадения по времени ответа процессора.

### 2.3. Защита сессий и токенов
- Сессионный токен формируется через `secrets.token_hex(32)` (256 бит энтропии).
- Срок действия сессии ограничен (7 дней) с проверкой `time.time() < expires_at`.
- Токены валидируются через заголовок `Authorization: Bearer <token>`.
- Реализован маршрут `/api/auth/logout` для немедленной аннуляции токена.

### 2.4. Изоляция и санитизация персональных данных (152-ФЗ)
- Функция `sanitize_user_dict()` гарантирует, что служебные поля `password_hash` и `password_salt` полностью удаляются перед отправкой в API и клиентский интерфейс.
- Файл конфигурации `.env` и файл базы данных `data/` включены в `.gitignore` и исключены из публичных репозиториев.

### 2.5. Двухфакторная верификация по E-mail (SMTP SSL)
- Коды верификации генерируются криптографически, имеют срок жизни 10 минут и удаляются сразу после успешного подтверждения.
- Все тестовые коды и подсказки удалены из клиентского кода и серверных ответов.
