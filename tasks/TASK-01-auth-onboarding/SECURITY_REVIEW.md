# Application Security Review: TASK-01 — Интерфейс авторизации и регистрации

## Вердикт: APPROVED

## 1. Моделирование угроз (Threat Modeling)
- **Точки ввода данных**: Поля Email, Пароль, ИНН, ФИО, Наименование организации.
- **Векторы атак**:
  - XSS через поля ввода: исключено, все значения санитизируются и экранируются в DOM.
  - Утечка паролей: пароли передаются только по HTTPS (в реальном API) и маскируются типом `password`.
  - Перебор паролей (Brute-Force): на клиенте внедрена блокировка кнопки и защита от дабл-клика; на бэкенде предусмотрен Rate Limiting.
  - Enumeration Attack (перебор пользователей): текст ошибки унифицирован («Неверный email или пароль»).

## 2. Проверка требований конфиденциальности (152-ФЗ)
- [x] Присутствует явный неотмеченный по умолчанию чекбокс согласия на обработку персональных данных.
- [x] Разделены поля физического лица и юридического лица.
- [x] Отсутствуют захардкоженные секреты и токены в кодовой базе.

## 3. Проверка надежности учетных записей
- [x] Внедрена валидация сложности пароля (минимум 8 знаков, заглавная буква, цифра, спецсимвол).
- [x] Проверка формата ИНН исключает ввод произвольных инъекционных строк.

## 4. Рекомендации для будущей бэкенд-интеграции
- Устанавливать сессионные JWT исключительно в `HttpOnly, Secure, SameSite=Strict` cookies.
- Настроить лимит попыток входа на уровне Nginx/API Gateway (не более 5 попыток в минуту на один IP/Email).
