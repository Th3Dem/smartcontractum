## 2. Анализ схемы и операций

### 2.1. Достаточность текущей схемы
Существующая структура таблиц `users` и `sessions` полностью покрывает требования функционала сброса пароля. Изменение схемы БД не требуется.

### 2.2. Запросы и транзакционная безопасность
1. **Поиск пользователя по E-mail**:
   ```sql
   SELECT * FROM users WHERE email = ?;
   ```
   *Оценка*: Использует уникальный B-Tree индекс `users(email)` $\rightarrow$ Сложность $O(1)$, время выполнения $< 0.1$ мс.

2. **Обновление пароля и инвалидация сессий**:
   ```sql
   UPDATE users SET password_hash = ?, password_salt = ? WHERE id = ?;
   DELETE FROM sessions WHERE user_id = ?;
   ```
   *Оценка*: Операции выполняются в рамках единого соединения и транзакции `conn.commit()`, гарантируя атомарность сброса учетных данных и разлогинивания всех предыдущих сессий.
