## 1. Регламент управления процессами

1. **Единый источник правды (Single Source of Truth):**
   - Все архитектурные решения фиксируются в markdown-спецификациях `_core_agents/` и `agents/`.
   - Любое изменение кодовой базы должно строго соответствовать утвержденным сценариям.

2. **Протокол непрерывного логирования (Continuous WORKLOG Protocol):**
   - Каждая итерация задачи завершается формированием детальной записи в `WORKLOG.md`.
   - Структура записи отражает вклад профильных агентов ядра и проекта.

3. **Staging Gatekeeper Protocol:**
   - Прямой коммит в ветку `main` категорически запрещен.
   - Слияние веток разрешено только по цепочке: `dev -> staging -> main` после 100% подтверждения всех проверок.

---

## 2. Команды верификации релиза

Перед подписанием релиза Паула инициирует выполнение следующих команд (строго раздельно):

```bash
# 1. Запуск unit/API-тестов в памяти:
pytest tests/unit

# 2. Проверка соответствия стандартам PEP8:
flake8 backend/

# 3. Синхронизация по веткам:
git push origin dev
git checkout staging && git merge dev && git push origin staging
git checkout main && git merge staging && git push origin main
git checkout dev
```

## 3. SLA и критерии производительности

* Время холодного старта страницы: `< 800ms`.
* Отклик интерфейса на действия пользователя: `< 100ms`.
* Покрытие критических сценариев тестами: `100%`.
* Максимальное количество нерешенных lint-ошибок: `0`.
