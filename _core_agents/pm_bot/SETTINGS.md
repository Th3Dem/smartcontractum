Для исключения таймаутов, падений и бесконечных запросов на ручное подтверждение (Edit/Create Approval) при делегировании задач субагентам:

1. **ОПЕРАЦИИ ЧЕРЕЗ ТЕРМИНАЛ**:
   Требовать от субагентов (py_bot, ui_bot, qa_bot, devops_bot, designer_bot, seo_bot) при массовом создании и правке файлов отдавать приоритет исполнению команд через консоль/терминал (Bash/Shell: cat, echo, sed, git, python-скрипты), если создание/правка через UI вызывает диалоги подтверждения.

2. **РЕЖИМ ALWAYS ALLOW**:
   Если операция требует работы напрямую через инструмент Edit/Create, субагент должен генерировать правки так, чтобы они подпадали под разрешенные правила окружения (Always Allow), либо завершать операцию атомарно без зависания в ожидании интерактивного ввода.

3. **АТОМАРНОСТЬ И ТАЙМАУТЫ**:
   Декомпозировать задачи для субагентов на маленькие итерации, чтобы каждый субагент успевал выполнить команду и вернуть статус выполнения до наступления Agent Execution Timeout.


4. **СТРОГАЯ ИЗОЛЯЦИЯ В WSL (/root/projects/smartcontractum)**:
   - ЗАПРЕЩЕНО копировать, дублировать или синхронизировать файлы проекта на диск C: (/mnt/c/Users/demya/... или C:\Users\demya\...).
   - Все операции (редактирование, создание файлов, запуск серверов/тестов, коммиты Git, обновление WORKLOG.md) производятся СТРОГО в директории /root/projects/smartcontractum/.
   - Запрещено создавать синхронизационные скрипты, завязанные на пути /mnt/c/.


5. **ОБЯЗАТЕЛЬНОЕ И НЕПРЕРЫВНОЕ ПОДРОБНОЕ ВЕДЕНИЕ WORKLOG.MD**:
   - На КАЖДУЮ задачу, фичу, багфикс или UI/UX-правку Паула (pm_bot) ОБЯЗАНА вносить детальную запись в /root/projects/smartcontractum/WORKLOG.md.
   - Запись должна включать:
     1. Временную метку и идентификатор релиза.
     2. Подробную декомпозицию вклада каждого задействованного субагента (pm_bot, designer_bot, ui_bot, py_bot, qa_bot, devops_bot, seo_bot).
     3. Точные списки измененных файлов и обоснование проектных/архитектурных решений.
     4. Метрики тестирования (количество пройденных unit-тестов, статус 100% GREEN).
     5. Хеш коммита Git и статус синхронизации веток (dev -> staging -> main).
   - Запрещено откладывать обновление WORKLOG.md на потом.
