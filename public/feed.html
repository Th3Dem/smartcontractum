Архитектура ● Сложный 8 мин

Архитектура децентрализованных оракулов для строительных контрактов: связка КС-2/КС-3 с ончейн-эскроу

Практическое руководство по сквозной автоматизации строительных взаиморасчетов. Разбор криптографической аттестации геодезических отметок, интеграции с ГИС ЕИС Закупки и прекомпилов ГОСТ Р 34.10-2012 в EVM.

</> SOLIDITY 0.8.26 + ГОСТ Р 34.10 ⛽ Gas Overhead: ~42.5k 
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.26;

interface IConstructionOracle {
    function verifyMilestone(bytes32 projectId, uint256 milestoneId, bytes calldata proof) external view returns (bool);
}

contract EscrowMilestonePayment {
    IConstructionOracle public immutable oracle;
    address public immutable treasury;

    event MilestonePaid(bytes32 indexed projectId, uint256 milestoneId, uint256 amount);

    constructor(address _oracle, address _treasury) {
        oracle = IConstructionOracle(_oracle);
        treasury = _treasury;
    }

    function releaseMilestone(bytes32 projectId, uint256 milestoneId, uint256 amount, bytes calldata proof) external {
        require(oracle.verifyMilestone(projectId, milestoneId, proof), "Oracle: Proof invalid");
        emit MilestonePaid(projectId, milestoneId, amount);
    }
}

1. Ключевые требования к оракулам в стройке

В строительных цепочках поставок ключевой риск — это несвоевременная оплата выполненных этапов либо подделка бумажных актов КС-2/КС-3. Смарт-контракт эскроу гарантирует, что средства списываются автоматически, как только электронный акт подписывается УКЭП технического заказчика в ГИС ЕИС Закупки.

2. Бенчмарки газа при верификации подписей ГОСТ

Использование прекомпилов ГОСТ Р 34.10-2012 снижает стоимость валидации подписи до 18,200 gas по сравнению с программной реализацией на чистом EVM.

Вопрос Баунти: 25 000 ₽ Решено

Как гарантировать конфиденциальность накладных УПД при передаче событий в смарт-контракт?

Проектируем B2B взаиморасчеты для оптовых поставок. Необходимо подтверждать факт отгрузки по накладной УПД, но сами спецификации позиций и цены не должны попадать в открытый блокчейн.

Принятый лучший ответ (Награда 25 000 ₽ выплачена)
Решение от Дарьи Вороновой (@daria_auditor):

Используйте схему Commit-and-Prove: в ончейн-контракт передается только keccak256(УПД + Salt) и ZK-SNARK доказательство того, что сумма превышает пороговую. Исходные строки накладной остаются исключительно в защищенном контуре 1С и передаются контрагенту по зашифрованному каналу.
