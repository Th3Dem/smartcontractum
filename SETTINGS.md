## 1. Технологический Enterprise-стек (Tech Stack)

### 🖥️ Серверный уровень (Backend & Storage):
- **Среда выполнения:** Python 3.12 (Strict MyPy Type Annotations, Asyncio).
- **Веб-фреймворк:** FastAPI 0.115+ / Starlette ASGI.
- **ASGI-сервер:** Uvicorn с пулом воркеров и оптимизацией keep-alive соединений.
- **Основная СУБД:** PostgreSQL 16+ (транзакционность, аудит смарт-контрактов, сессионные данные) через `asyncpg` и `SQLAlchemy 2.0`.
- **In-Memory хранилище и очереди:** Redis 7+ (кэширование ответов LLM, распределенные локи, очереди задач SAQ/Celery).
- **Валидация:** Pydantic v2 (строгие DTO-модели для всех контрактов и API).

### 🤖 Интеграция ИИ (AI Engine & Circuit Breaker):
- **Основной провайдер:** Google Gemini REST API (`v1beta/models/gemini-flash-latest`) в режиме Structured JSON.
- **Отказоустойчивость (Circuit Breaker):**
  - Реализация на базе `pybreaker` / `tenacity` с тремя состояниями (*Closed*, *Open*, *Half-Open*).
  - Порог сбоев: 3 подряд таймаута / ошибки 503/429 переключают контур в *Open* на 30 секунд.
- **Детерминированный (Deterministic) Fallback:**
  - При недоступности облачной LLM система мгновенно переключается на локальный детерминированный семантический процессор.
  - Нулевая вероятность отказа или зависания интерфейса для пользователя.

### 🎨 Клиентский уровень (Frontend Build):
- **Сборщик:** Vite (мгновенный HMR, оптимизированный бандлинг).
- **Стилизация:** PostCSS + Tailwind CSS v3 (адаптивная сетка, дизайн-токены, обсидиановая тема Helias).
- **Интерактивные виджеты:** Vanilla JavaScript ES6+ (без тяжелых runtime-зависимостей).
- **Шаблонизация:** Jinja2 с поддержкой i18n (RU / EN) и сохранением контекста в защищенных Cookie.

### 📊 Наблюдаемость и мониторинг (Observability):
- **Отслеживание ошибок:** Sentry SDK (runtime-ошибки бэкенда, необработанные JS-исключения, контекст сессий).
- **Метрики и телеметрия:** Prometheus client + Grafana (RPS, латентность Uvicorn p50/p95/p99, время ответа LLM, кэш-хиты Redis).
- **Аудит безопасности:** Логирование в формате JSON с маскированием персональных данных.

## 2. Релизный протокол и ветвление (Staging Gate Protocol)

### 🌿 Структура веток:
```
feature/* ──► dev ──► staging ──► main (Production)
```
> ⛔ **КРИТИЧЕСКОЕ ПРАВИЛО:** Прямой коммит и прямой автоматический мердж в ветку `main` **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНЫ**.

### 🚦 Staging Gate Protocol (Правила допуска в Production):
Мердж ветки `staging` в `main` и деплой на Production разрешены **ТОЛЬКО** при одновременном выполнении условий:

1. **Автоматический прогон Unit & API тестов:**
   - `pytest -v --cov=backend tests/unit` (100% критических путей пройдено, 0 ошибок).
   - Статический анализ: `flake8 .`, `black --check .`, `mypy backend/`.
2. **Сквозные E2E-тесты интерфейса:**
   - Playwright сценарии (`tests/e2e`) успешно прошли в headless-браузерах Chromium, Firefox, WebKit.
3. **Нагрузочные испытания (Load Testing):**
   - Нагрузочный прогон `k6 run tests/load/load_test.js` подтверждает стабильность при пиковой нагрузке (p95 latency < 350ms, 0% drop rate).
4. **AppSec / SAST сканирование:**
   - Проверка безопасности контейнеров и зависимостей (Trivy / Bandit) без уязвимостей уровня High / Critical.
5. **Ручной допуск (Gatekeeper Approval):**
   - Финальная верификация и подпись релиза от `pm_bot` (Paula) и `devops_bot`.
